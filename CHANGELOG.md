## [0.1.0] — 2026-09-29

Initial release. The scope is deliberately narrow: parse and serialise RFC 4180
CSV, report structural problems, and nothing else.

### Added

**Library**

- `parse`, `parse_strict`, `parse_with` — a single forward pass over the input
  producing `Array[Array[String]]` (`Table`).
- `serialize`, `serialize_with`, `serialize_row`, `needs_quoting` — an RFC 4180
  serialiser that quotes exactly when the grammar requires it.
- `Dialect` with constructors `rfc4180`, `strict_crlf`, `strict_lf`, `semicolon`,
  `tab`, `excel`, plus `with_delimiter` and `with_bom_stripping`. The default
  dialect follows RFC 4180 errata 5664: CRLF, bare LF and bare CR are all
  accepted as record separators; the `strict_*` dialects restrict this.
- `CsvError` with four variants — `UnterminatedQuotedField`,
  `UnescapedQuoteInQuotedField`, `UnexpectedLineBreak`, `FieldCountMismatch` —
  each carrying a 1-based `Position`. `CsvError::to_message` renders a
  human-readable description.
- `diagnose` — structural analysis that does not reject input: ragged rows,
  blank lines, duplicate header names, and header shape problems, collected into
  a `Report` with `is_clean` and `to_lines`.
- `looks_like_header` — a conservative heuristic for "is the first record a
  header row", documented as a heuristic rather than a decision procedure.

**Command line tool**

- `csvkit count <file>` — record, field and column counts, plus an issue count.
- `csvkit check <file>` — structural diagnostics, one per line.
- `csvkit csv <file>` — re-serialise through the library to stdout.
- `csvkit version` — print the library version.
- Exit codes: `0` success, `1` a CSV error or reported issue, `2` a usage or
  I/O error, so a malformed file and a mistyped command are distinguishable
  without parsing stderr.

**Tests**

- 28 conformance tests pinning the RFC 4180 grammar case by case: the two
  worked examples from the RFC, optional trailing CRLF, quoted commas, doubled
  quotes, embedded CRLF and bare LF, empty fields, quoted-empty versus no
  record, LF / CR / mixed line endings, both strict dialects, `"abc"def` as an
  error, unterminated quotes, error positions, BOM handling, multibyte UTF-8,
  and the semicolon and tab dialects.
- A differential conformance suite: 1078 documents generated by Python 3.13's
  `csv` module, parsed by `csvkit`, compared field-for-field against the
  records Python recovers. This is the project's external-consistency evidence.
- A round-trip suite over every differential corpus table and over hand-written
  tables exercising each quoting rule in isolation.
- Writer and diagnostics suites pinning the quoting predicate and each
  diagnostic's wording and position.

**Repository**

- `tools/gen_differential.py` — deterministic corpus generator (seed 20260929),
  standard library only, with a self-check that the generator never emits an
  expectation it cannot itself reproduce.
- `NOTICE` — provenance: no code was ported, and Python's `csv` is used as a
  test oracle rather than redistributed.
- CI covering type check with warnings denied, a build of every target, the test
  suite, the CLI, corpus reproducibility, and packaging.
